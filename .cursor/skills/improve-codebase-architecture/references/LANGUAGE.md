# 语言词汇表（Language）

本技能所有建议中的共享词汇。**严格使用这些术语**——不要替换成"component"、"service"、"API"或"boundary"。一致的语言才是重点。

## 术语

**模块（Module）**  
任何有接口和实现的东西。刻意不限定规模——同等适用于函数、类、包或跨层切片。  
_避免_：unit、component、service。

**接口（Interface）**  
调用者正确使用模块所需了解的一切。包含类型签名，但也包括不变量、顺序约束、错误模式、所需配置和性能特征。  
_避免_：API、signature（过窄——这些词只指类型层面的表面）。

**实现（Implementation）**  
模块内部的代码。有别于**适配器**：一个东西可以是小适配器配大实现（Postgres 仓储），也可以是大适配器配小实现（内存 fake）。讨论接缝时用"适配器"；其他情况用"实现"。

**深度（Depth）**  
接口处的杠杆——调用者（或测试）每单位接口学习成本可以触发的行为量。模块**深**意味着大量行为隐藏在小接口后面；模块**浅**意味着接口几乎和实现一样复杂。

**接缝（Seam）**（来自 Michael Feathers）  
可以不在该处编辑就改变行为的地方。模块接口所在的**位置**。选择在哪里放接缝是独立的设计决策，和放什么在接缝后面无关。  
_避免_：boundary（与 DDD 的有界上下文重叠）。

**适配器（Adapter）**  
在接缝处满足接口的具体实现。描述**角色**（填充哪个槽），而非内容（里面是什么）。

**杠杆（Leverage）**  
调用者从深度获得的东西。每单位接口学习成本获得更多能力。一个实现在 N 个调用点和 M 个测试中偿还成本。

**局部性（Locality）**  
维护者从深度获得的东西。变更、Bug、知识和验证集中在一个地方，而不是分散到各调用者。修一处，处处修。

## 原则

- **深度是接口的属性，不是实现的属性。** 深模块内部可以由小的、可 Mock 的、可替换的部分组成——它们只是不属于接口。模块可以有**内部接缝**（对实现私有，供自身测试使用）和**外部接缝**（在接口处）。
- **删除测试。** 想象删掉这个模块。如果复杂度消失，模块什么都没藏（它是透传层）。如果复杂度在 N 个调用者处重新出现，模块值得存在。
- **接口是测试表面。** 调用者和测试穿越同一接缝。若你想测试"绕过"接口，模块的形状可能不对。
- **一个适配器意味着假设性接缝。两个适配器才意味着真实接缝。** 除非某个东西实际上在接缝两侧有变化，否则不引入接缝。

## 关系

- 一个**模块**只有一个**接口**（它向调用者和测试展示的表面）。
- **深度**是**模块**相对于其**接口**的属性。
- **接缝**是**模块**的**接口**所在之处。
- **适配器**在**接缝**处满足**接口**。
- **深度**为调用者产生**杠杆**，为维护者产生**局部性**。

## 拒绝的框架

- **深度 = 实现行数 / 接口行数**（Ousterhout）：鼓励填充实现。我们用"深度即杠杆"替代。
- **"接口"即 TypeScript `interface` 关键字或类的公共方法**：过窄——这里的接口包括调用者必须了解的每一个事实。
- **"边界（Boundary）"**：与 DDD 的有界上下文重叠。说**接缝**或**接口**。
